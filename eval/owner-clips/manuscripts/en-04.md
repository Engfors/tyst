I: How do you manage infrastructure in your team today?
G: Almost everything is defined in Terraform. We keep the code in GitHub, and every change goes through a pull request that someone else has to review. When the pull request is merged, a pipeline runs the plan and applies it, first to staging and then to production.
I: What about secrets?
G: Those live in HashiCorp Vault. Applications get short-lived credentials from Vault when they start, so we don't have passwords lying around in config files. It took a while to set up, but it's one of the best decisions we've made.
I: And the applications themselves?
G: They run as containers on Kubernetes. We package each service with Helm, so a deploy is basically a new chart version going through the same pipeline. If something looks wrong in staging, we simply don't promote it.
I: What's the biggest headache?
G: State drift. Someone changes a setting by hand in the cloud console during an incident, and then Terraform no longer matches reality. We run a nightly job that detects state drift and posts it in our team channel, so at least we find out quickly.
